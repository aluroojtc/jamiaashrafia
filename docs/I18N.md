# Languages: English, اردو, العربية

The portal runs in English, Urdu or Arabic. Urdu and Arabic pages are right-to-left.

## How it works

| Piece | File |
|---|---|
| Language choice, page direction, live translation, `I18n.t()`, language menu | `js/i18n.js` |
| Urdu / Arabic catalogs (English text → translation) | `js/i18n/ur.js`, `js/i18n/ar.js` |
| Language menu styles, Urdu/Arabic fonts, right-to-left fixes | `css/i18n.css` |
| Account language (`user_credentials.preferred_language`, `POST /api/auth/language`) | `server/auth.js`, `server/lms-api.js` |

- **English is the source.** Templates keep their English text. The catalogs map that exact text to Urdu and Arabic, so English pages need no catalog and load nothing extra.
- **Live translation.** On Urdu and Arabic pages, `js/i18n.js` translates text and the `title`, `placeholder`, `aria-label` and `alt` attributes as modules render. It also translates `alert` / `confirm` / `prompt` messages and the server's error messages.
- **Placeholders.** A catalog key may contain `{n}` (any number) or named placeholders such as `{name}`. For example, `'{n} students enrolled'` matches "12 students enrolled". Labels joined with ` • `, ` — ` or ` – ` are translated part by part, and trailing `:`, `*`, `…` are handled automatically.
- **Sentences around markup.** When a sentence wraps a name or link in `<strong>`/`<a>`, build it with
  `I18n.t('Delete the custom role {name} ({id})?', { name: '<strong>…</strong>', id: '…' })` so it is translated whole.
- **Records are not translated.** Names, kitab titles, addresses and notices that people type stay as typed. Where a record has an Urdu/Arabic name (`urduName`, `urduTitle`, `arabicTitle`), `Lms.localName(english, native)` shows that name on Urdu/Arabic pages *instead of* the English one, never both together.
- **Dates and stored text stay English.** `Lms.fmtDate()` still produces "17 Oct 2026", because its output is saved inside notifications. Pages translate month names when they display the text.
- **Opting out.** Add `translate="no"` to any element whose text must never be translated.

## Choosing and remembering the language

- Login page: dropdown in the card's top corner. App: globe button in the header, beside notifications.
- Order of precedence: language saved on the account → language picked on this device → browser language → English.
- Changing the language saves it on the device (`localStorage.JAMIA_LANG`) and, when signed in, on the account. Then the page reloads in that language.
- A language picked on the login page is saved on the account at sign-in. An account's saved language follows the person to any other device.

## Adding or changing text

1. Write the English text in the template as usual.
2. Add the same English text as a key to **both** `js/i18n/ur.js` and `js/i18n/ar.js`.
3. Run `npm run i18n:check`. It confirms the two catalogs match and that every `I18n.t()` key has a translation.
4. Open the page in Urdu and Arabic and run `I18n.missingStrings()` in the browser console. It lists English text shown without a translation (record data such as names also appears there and is expected).
5. When you change a catalog, raise `CATALOG_VERSION` in `js/i18n.js` so browsers fetch the new file.

## Right-to-left layout

Stylesheets and inline styles use logical properties (`margin-inline-start`, `padding-inline-end`, `inset-inline-start`, `text-align: start`). Keep using them instead of `left` / `right`, so layouts mirror automatically. Direction-sensitive icons (arrows, chevrons, sign-in/out) are mirrored in `css/i18n.css`.
